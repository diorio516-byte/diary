# 밸런스게임 다음 날 리포트 — 만드는 순서와 규칙

처음 작성: 2026-10-23 (인계서를 공개 저장소용으로 옮김 · 개인 자료 없이 방법과 형식만).
재준 규칙: 만들기 전에 미리보기(시안)와 방향을 먼저 보여 주고 승인받는다. 설명은 쉬운 말로, 한 번에 할 일 하나만, 누를 버튼과 끝나면 보낼 말까지 적는다.

> 상태: 2026-10-23 시안 4장 승인(재준 「다 좋아 추천 다 좋아」). ① 밤 11:23 「우리 리포트」 → 아침 7:23 리포트 하나로 합침(매달 1일엔 그 자리에서 월간) ② 애인 공략하기 = 리포트마다 새 에피소드 ③ 고른 이유 = 고른 직후 보기 3~4 + 직접 쓰기 + 건너뛰기.
> 예약 작업 모델: **Opus 5.5 · 품질 우선**(재준 10/23 「토큰 걱정 말고 품질 우선으로 Opus 5.5 노력 최대」 — 아래 2절의 Sonnet 은 바뀜).

## 1. 목표
밸런스게임을 한 날 → 다음 날 오전 9시 전에 두 사람의 결과 리포트를 앱에 올리고 알림을 보낸다.

## 2. 정해진 것 (재준 결정, 2026-10-23)
- 보는 사람: 재준·현지 둘 다. 알림도 둘 다. 말투도 두 사람에게 맞춘다.
- 분량: 매번 심층 리포트, 매달 1일엔 월간 심층 리포트를 따로.
- 받는 곳: 앱 화면만(PDF 없음).
- 고른 이유: 문항마다 「고른 이유」 보기를 주고 눌러서 고르게 한다. 보기를 만들기 어려운 문항은 직접 쓰기. 둘 다 건너뛸 수 있는 선택 입력.
- 한 명만 답한 날: 리포트 없이 「○○ 님 답 기다리는 중」 알림만. 둘 다 답한 다음 날 아침에 리포트.
- 시간: 매일 아침 7시 반쯤(한국 시간) 시작해 9시 전에 끝. 실패하면 재준에게만 알림. 게임이 없던 날은 아무것도 안 하고 끝.
- 예약 작업 모델: Sonnet. 월간 리포트가 얕으면 그때 Opus 로.

## 3. 절대 지킬 것
1. 다른 프로젝트의 개인 자료는 이 앱에 넣지 않는다. 가져오는 건 분석 방법과 형식뿐이다.
2. 밸런스게임은 정식 심리검사가 아니다. 점수·구간·「궁합 ○점」·진단명을 쓰지 않는다. 「고른 답으로 본 경향」이라고 쓴다.
3. 돈·가격 내용은 넣지 않는다. 돈 관련 문항은 리포트에서 다루지 않는다.
4. 두 사람을 공정하게 쓴다. 한쪽만 고칠 사람으로 쓰지 않는다. 다른 답은 틀린 답이 아니다.
5. 마음을 추측하지 않는다. 각자 고른 답과 이유만 근거로 쓴다. 궁금한 건 「서로 물어볼 질문」으로 바꾼다.
6. 문항 하나로 판정하지 않는다. 여러 문항이나 여러 날에 되풀이된 것만 결론으로 쓴다.
7. 사실(고른 답·이유)과 해석을 나눈다. 추측에는 [가설·확신 높음/중간/낮음]을 붙인다.
8. 학자가 두 사람을 직접 본 것처럼 꾸미지 않는다. 「○○ 연구의 틀로 보면」이라고 쓴다. 오은영 박사 시각은 「공개 발언의 틀을 빌린 것」이라고 표시한다.
9. 쉬운 말, 해요체, 짧은 문장. 비유는 쓰지 않는다. 듣기 좋기만 한 말도, 깎아내리는 말도 쓰지 않는다.
10. 민감한 이야기가 이유 칸에 나오면 사실만 적고 해석하지 않는다.

## 4. 분석 방법
고른 답 = 검사, 고른 이유 = 면담·문장완성, 매번 리포트 = 보고서, 월간 리포트 = 전문가 관점 종합 역할.
매번 하는 순서:
1. 기록: 어제 문항, 두 사람이 고른 답과 이유를 해석 없이 기록 파일에 저장.
2. 비교: 같은 답과 다른 답을 나눈다. 다른 답은 세 칸 — 같이 정해야 할 것(생활에 부딪힘) / 대화거리 / 그대로 둬도 되는 취향 차이.
3. 누적: 지금까지 쌓인 기록과 비교해 되풀이되는 것을 찾는다.
4. 관점: 그날 문항에 맞는 관점을 모두 쓴다(보통 4~6개, 6절).
5. 작성 → 앱에 올림 → 알림.

## 5. 리포트 형식 (매번 심층, 앱 화면)
1. 세 줄 결론 카드: 잘 맞는 것(초록) / 다른 것(주황) / 같이 해 볼 것(파랑)
2. 해 볼 것: 오늘 할 것 하나와 서로 물어볼 질문 하나
3. 겹치는 자리: 주제 × 관점 표에 ● — 되풀이되는 게 한눈에
4. 관점별 근거(접기·펼치기): 이론 한 줄 → 세 줄(이런 두 사람이에요 / 그래서 이럴 수 있어요 / 그래서 이걸 해 보세요) → 근거(문항과 각자 고른 답·이유)
5. 다른 답 세 칸 정리
6. 맨 뒤(접힘): 문항별 두 사람의 답과 이유 표, 같은 답 개수(숫자는 여기에만), 출처, 「해석이며 진단이 아님」
- 지난 리포트와 같은 결론은 「지난번과 같음(날짜)」 한 줄.
- 사진: 이미지 작업 프로세스대로, 그날 다이어리에 사진이 있으면 맨 위에 한 장(「글만」이면 뺌).

월간 심층(매달 1일): 지난달 기록 전체로 — 세 줄 결론 → 할 일 세 개(이번 달 / 같이 살기 전 / 그다음) → 겹치는 자리 표 → 관점별 세 줄 → 맨 뒤에 기록과 출처.

## 6. 관점 목록 (커플용)
- 가트맨 연구: 사랑의 지도(서로를 얼마나 아는지), 관심 요청에 돌아보기, 풀리지 않는 차이를 다루는 법
- 성인 애착: 가까이 있고 싶을 때와 혼자 있고 싶을 때
- 자기확장 모델(아론): 새로운 경험을 같이 하기
- 가치관(슈워츠): 안정·도전·전통·자유 같은 우선순위
- 갈등·대화 방식: 부드럽게 시작하기, 회복 시도
- 생활 리듬과 집안일 나누기: 공정하다고 느끼는지
- 애정 표현 방식: 「사랑의 언어」는 대중 개념이고 연구 근거가 약하다고 표시하고 쓴다
- 성인 발달(에릭슨): 친밀감, 함께 가정을 이루는 시기의 과제
- 오은영 박사 시각: 아이·양육 문항이 나올 때만, 공개 발언의 틀을 빌린 것이라고 표시
- 돈의 심리: 쓰지 않는다(3절 3항)
출처: 이론은 기본 문헌을 맨 뒤에. 통계처럼 바뀌는 사실은 검색해서 링크.

## 9. 말투 — 공부가 아니라 놀이 (재준 10/23 「전문용어·학술 용어 대신 일상에서 쓰는 쉬운 말로 · 공부하는 게 아니고 노는 거잖아 · 부담감」)
- 학자 이름·연구 이름·전문 용어는 화면 글에 쓰지 않는다. 출처는 맨 아래 접힌 곳에만(새 화면이 들어오기 전엔 생략).
- 관점은 이 쉬운 이름으로만 쓴다:
  | 화면 이름 | (안쪽 근거 — 화면엔 안 씀) |
  |---|---|
  | 🎢 같이 새로운 거 해 보기 | 자기확장(아론) |
  | 🧭 우리가 중요하게 여기는 것 | 가치(슈워츠) |
  | 🗺 서로 얼마나 알까 | 사랑의 지도(가트맨) |
  | 🤝 가까이 · 따로 | 성인 애착 |
  | 💬 말 거는 법 | 갈등·대화(가트맨 부드럽게 시작·회복 시도) |
  | 🧺 생활 나누기 | 생활 리듬·집안일 |
  | 💌 마음 표현 | 사랑의 언어(대중 개념) |
  | 🏡 함께 꾸릴 날 | 성인 발달(에릭슨) |
  | 👶 아이 이야기 | 오은영 박사 공개 발언의 틀 |
- 짐작 표시: 「꽤 확실해요」 / 「🤔 아마 그럴걸요」 / 「살짝 짐작」 (= 가설·확신 높음/중간/낮음).
- 다른 말: 세 줄 결론 → 「한눈에 셋」 · 근거 → 「우리가 고른 것」 · 다른 답 세 칸 → 「같이 정할 것 / 수다거리 / 그냥 취향」 · 해 보세요 → 「이렇게 해 볼까요?」 · 작은 실천 → 「작은 챙김」 · 서로 사전 → 「○○ 알아 가기」 · 확인됨 → 「확실해요(두 번 넘게 골랐어요)」.

## 11. 아침 리포트가 쓰기 전에 꼭 할 것 — 품질 점검 (밤 리포트에서 옮김 · 재준 10/23 「토큰 걱정 말고 품질 우선」)
모델을 바꾸자거나 토큰을 아끼자는 권유는 하지 않고, 시간이 걸려도 아래를 빠짐없이 한다.
0) 앱 「우리 분석」 읽기(저장소 밖에 풀기, 읽기만): `python3 $R/dev/srcbox.py open --dir $W/src >/dev/null` 뒤
   balin.json.enc 가 있으면 그것(ghsync keys_for · open_bytes), 없으면 $W/src/content/play.json 의 balInsight 를 $W/analysis.json 으로. 끝나면 쓰든 안 쓰든 `rm -rf $W/src`.
1) 먼저 세기: Python 으로 delta 를 줄마다 풀어(밸런스 문제마다 재준·현지 선택·같음/다름, 서로 맞히기, 질문 답, 기분 …) 센다. 「누가 무엇을 골랐다」는 이 결과에서만 가져온다.
2) 묶어 읽기: 하나씩 늘어놓지 말고 고른 답을 2~3개 이야기로 묶고, 묶음마다 실제 선택 2~4개를 근거로 댄다. 결론은 둘 이상 문제나 여러 날에 되풀이된 것만. 문제 하나에서 보인 건 결론 대신 「오늘 해 볼 것」이나 ask 의 서로 물어볼 질문으로. 반대 사례(같이 고른 답 등)가 있으면 같이 적는다. 「다 · 모두 · 셋 다 · 항상」은 그 묶음에 예외가 하나도 없을 때만, 무엇이 같았는지 이름을 대고(10/23 밤 판 제목 「「우리」 질문은 다 같았어요」는 답이 갈린 문제가 여럿 있어 틀렸음).
3) 쌓인 기록과 잇기: analysis.json(우리 분석의 profiles · diffs)과 어제 선택이 맞는지 · 반대인지 한 번은 짚는다. prev 의 ask · 해 볼 것을 했으면 한 줄로 이어 받는다. 「누구는 ~한 사람」으로 굳히지 말고 「~한 편」.
4) 화면에 맞추기(지금 앱 「우리 리포트」): 첫 블록만 펼쳐 보이고 둘째 블록부터는 접혀서 h 와 p 첫 문장 앞 34자만 보인다 → 둘째 블록부터 첫 문장은 34자 안의 한 줄 요약. p 안 줄바꿈은 화면에 안 보인다(「 / 」로 나누기). ask 는 💬 질문 + 둘이 한 줄(80자)씩 쓰는 메모 칸 → 둘 다 한 줄로 답할 수 있는 질문. 리포트는 그 메모 답을 못 읽으니 「다음에 읽을게요」 같은 약속은 하지 않는다.
5) 다시 보기: 다 쓰면 ① 글에 나온 선택마다 delta 와 맞는지 Python 으로 확인 ② Agent(general-purpose) 하나에게 rep.json · delta · analysis.json · 이 문서 3·9·11절을 주고 사실과 다른 말 · 과장 · 근거 없는 해석 · 금지어 · 전문 용어 · 한쪽 깎는 말 · 어색한 한국어를 찾게 한다(파일은 고치지 말고 목록만). high 는 모두, medium 은 맞는 것만 고친다.

## 12. 「어젯밤」의 범위와 첫 회 (재준 10/24 새벽 「당일 저녁에 한 밸런스 → 다음 날 오전에 리포트 작성 완료된 채로 알림」)
